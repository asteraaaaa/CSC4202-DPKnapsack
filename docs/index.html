Problem Statement

Efficient distribution of limited relief supplies during flood disasters in Kelantan

Flood Disaster in Kelantan

After a massive flood in Kelantan, rescue teams rely on small boats with limited weight capacity to deliver vital items like food, medicine, and clothing. Since each item has a different urgency and weight, the challenge is to pack the most valuable items without overloading the boat. This project aims to create an algorithm that picks the best combination of items to help flood victims effectively.

Challenge

Every item has a unique weight and value, with the value indicating urgency and significance to the rescue effort. The challenge is to pack the most valuable combination of materials without exceeding the boat's maximum weight limit.

Constraints

  • Each item is either taken or not (0/1 decision)
  • Total weight must not exceed maximum boat weight
  • Limited transportation capacity
  • Urgent time requirements

Output

  • List of selected items
  • Total value and weight
  • Remaining capacity
  • Visual summary of choices

Full Scenario

The Kelantan flood left many areas underwater, blocking roads and isolating communities. Boats became the only way to send supplies. Each item to be delivered has a weight and an urgency value (how important it is). No item can be split. So, we need a smart way to choose which items go into the boat to help the most people.

Our project offers a Java-based system that uses an optimization algorithm. Users can input item data and boat capacity, and the system will output:

  • The selected items
  • Total weight and value
  • Remaining boat capacity
  • A visual summary of results

This combines real-world humanitarian needs with computer algorithms to improve how fast and fairly help is delivered.

Scenario Overview

  • Location: Kelantan, Malaysia
  • Disaster: Major Flood (Northeast Monsoon)
  • Problem: Roads are blocked, only boats can be used, resources are limited
  • Goal: Send the most important items in each trip without exceeding boat weight
  • Expected Output: Selected item list, total weight, value, and remaining capacity

Why A Solution Is Important

1. Saving Lives

When the right items are chosen, critical supplies like medicine reach victims faster — potentially saving lives.

2. Resource Limitations

Boats and fuel are limited. If packing is optimized, fewer trips are needed to deliver more valuable goods.

3. Time Sensitivity

Flood conditions change rapidly. A good algorithm gives quick and smart decisions, so rescuers don't waste time.

4. Fairness and Efficiency

If we use space wisely, every kilogram of the boat helps those who need it most. No room is wasted on low-priority items.

Algorithm Selection

Comparing approaches to solve the relief distribution optimization problem

Comparison of Approaches

Divide and Conquer

Strengths:

  • Makes the problem easier to understand
  • Natural structure and logic

Weaknesses:

  • No memory used to store past results, so it can be slow
  • Inefficient without optimization like memoization
  • Not ideal for large input problems

Greedy

Strengths:

  • Very fast and simple
  • Great for situations where items can be divided (fractional knapsack)

Weaknesses:

  • Not suitable when you must take the whole item or leave it (0-1 Knapsack)
  • May miss better combinations by choosing too quickly

Dynamic Programming

Strengths:

  • Best suited for 0-1 knapsack problems
  • Always gives the correct, optimal result
  • Can be done using table (bottom-up) or recursion (top-down with memory)

Weaknesses:

  • Uses more memory and time for large problems
  • Needs careful coding to be efficient

Chosen Algorithm

We select Dynamic Programming (DP) because our relief-packing problem is a classic 0-1 knapsack problem. In this scenario, each item can either be taken or left behind (0-1 choice). The goal is to maximize the total value (urgency) of items loaded in a boat without exceeding its weight limit, exactly matching the knapsack definition.

By analogy:

  • Items: The relief supplies (each with a weight w_i and a value v_i)
  • Capacity: The boat's maximum weight W
  • Objective: Maximize ∑vᵢ of selected items such that ∑wᵢ ≤ W

DP is well-suited here because it considers all combinations of items through a systematic process. We implement the bottom-up DP (tabulation) approach: we construct a 2D table dp[i][j] representing the maximum value achievable with the first i items and capacity j.

Recurrence Relation:

If the weight of item i is less than or equal to j, then:

dp[i][j] = max( dp[i-1][j], dp[i-1][j - w[i]] + v[i] )

(This means we take the better of either not including or including item i.)


Else, if the item doesn't fit:

dp[i][j] = dp[i-1][j]

By filling this table iteratively for i = 1..n and j = 1..W, we ensure every subproblem is solved optimally, building up to dp[n][W], which represents the maximum value for all items at full capacity. Once the table is complete, we trace back from dp[n][W] to identify which items were included in the optimal solution.

Algorithm Implementation

Java implementation of the Dynamic Programming solution for the 0/1 Knapsack problem

Problem Formulation

Formally, let there be n items. Each item i has weight w_i and value v_i. Boat capacity is W. We want to choose a subset S of items to maximize:

Subject to

Each item is either taken (1) or not (0), giving it the 0-1 knapsack structure.

Table Initialization

We initialize a dynamic programming (dp) table dp to store the maximum value achieveable for each possible weight from 0 up to the given capacity. The n array keeps track of which item was chosen:

int n = items.size();

int[][] dp = new int[n + 1][capacity + 1];

Filling the DP Table

The DP table is filed by iterating over each item and updating the table in reverse order to prevent overwriting values that are yet to be processed. For each item, we consider its weight and value:

for (int i = 1; i <= n; i++) {

Item item = items.get(i - 1);

for (int w = 0; w <= capacity; w++) {

if (item.getWeight() > w) {

dp[i][w] = dp[i - 1][w];

} else {

dp[i][w] = Math.max(dp[i - 1][w], dp[i - 1][w - item.getWeight()] + item.getValue());

}

}

}

This loop ensures that for each possible capacity increment, we store the maximum values achievable either by including or excluding the current item.

Tracing Back the Selected Items

After filling the DP table, we trace back through it to determine the selected items. Starting from the maximum capacity, we track which items were chosen and how many were selected:

int totalWeight = 0;

int remainingValue = dp[n][capacity];

int w = capacity;

List selectedItems = new ArrayList<>();


for (int i = n; i > 0 && remainingValue > 0; i--) {

if (dp[i][w] != dp[i - 1][w]) {

Item item = items.get(i - 1);

selectedItems.add(0, item); // insert at the beginning to keep original order

totalWeight += item.getWeight();

remainingValue -= item.getValue();

w -= item.getWeight();

}

}

Summary

This project applies dynamic programming by constructing a table that records the maximum achievable value for each capacity level. By iterating through items and updating the table in reverse, the algorithm efficiently determines the optimal combination of items without exceeding the weight limit. This approach enables accurate, informed decision-making based on available capacity and priority of needs.

Correctness Proof

Mathematical validation of our Dynamic Programming solution

Base Case

We initialize dp[0][w] = 0 for all w in 0 to W. This correctly represents that with 0 items, the maximum value is 0.

Induction Hypothesis

For items 1 to i-1, dp[i-1][w] correctly represents the maximum value achievable with capacity w.

Induction Step

For item i, we correctly compute dp[i][w] by considering both inclusion and exclusion cases.

Recurrence Relation

dp[i][w] = max(dp[i-1][w], dp[i-1][w - wᵢ] + vᵢ) if wᵢ ≤ w

dp[i][w] = dp[i-1][w] otherwise

This relation ensures we always make the optimal choice at each step, building up to the global optimum.

Inclusion Case

If we include item i, we add its value vᵢ to the optimal solution for the remaining capacity (w - wᵢ).

Exclusion Case

If we exclude item i, we carry forward the optimal solution from the previous items (i-1).

Final Verification

By mathematical induction, we've proven that our DP solution correctly computes the optimal value. The traceback procedure then correctly identifies which items contribute to this optimal value.

Algorithm Analysis

Comprehensive evaluation of time and space complexity

Time Complexity

O(nW) where n = number of items, W = capacity. The nested loops over n and W ensure all subproblems are solved.

Space Complexity

O(nW) for the DP table. Can be optimized to O(W) by using a 1D array and updating in reverse.

Optimality

Guaranteed to find the optimal solution by systematically evaluating all possible combinations.

Complexity Cases

Case Time Space Description
Best Ω(nW) O(nW) Entire DP table must be filled
Average Θ(nW) O(nW) No early exits; consistent performance
Worst O(nW) O(nW) Maximum iterations required

  • Clear traceback procedure
Limitations

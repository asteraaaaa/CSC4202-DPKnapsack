Problem Statement

Flood Disaster in Kelantan

In the aftermath of a major flood in Kelantan, rescue logistics workers must use boats with limited carrying capacity to convey vital relief supplies, including food, medication, tools, and clothing.

Challenge

Every item has a unique weight and value, with the value indicating urgency and significance to the rescue effort. The challenge is to pack the most valuable combination of materials without exceeding the boat's maximum weight limit.

Constraints

  • Each item is either taken or not (0/1 decision)
  • Total weight must not exceed maximum boat weight
  • Limited transportation capacity
  • Urgent time requirements

Output

  • List of selected items
  • Total value and weight
  • Remaining capacity
  • Visual summary of choices

Scenario Overview

In the aftermath of severe flooding in Kelantan, vast areas were left submerged, rendering roads impassable and cutting off thousands of residents from access to essential supplies. In response, rescue and logistics teams were deployed to deliver critical relief items such as food, medicine, tools, and clothing. Due to the flood conditions, boats with limited carrying capacity served as the only viable mode of transportation.

Given the urgency and the limited transport capacity, it became crucial to determine which combination of items should be transported on each trip to maximize their impact. Each item differed in both weight and importance (urgency), and no item could be split across trips. Therefore, the key challenge was to develop a solution that could maximize the total value of the items transported without exceeding the boat's weight limit.

Why This Matters

Efficiently solving this packing problem is critical because it directly impacts human lives. Delays or suboptimal choices mean fewer essential supplies reach people who urgently need them. In our context, every kilogram of boat capacity must be used to its maximum benefit.

Key Benefits of an Optimal Solution

  • Saving lives: Choosing the most urgent supplies first ensures that limited relief reaches those in greatest need, potentially reducing casualties.
  • Resource constraints: Boats and fuel are limited. An optimal packing means fewer trips required to deliver the same total value, conserving time and effort.
  • Time-critical response: In fast-changing flood conditions, an algorithmic packing plan allows quick decision-making.
  • Equity and impact: Ensuring that the combination of items is best possible increases fairness.

Algorithm Selection

Comparison of Approaches

Divide and Conquer

Strengths:

  • Good for understanding problem structure
  • Applies problem decomposition

Weaknesses:

  • No memorization leads to repeated calculations
  • Inefficient for large inputs
  • High time complexity without optimization

Greedy Programming

Strengths:

  • Very fast and simple to implement
  • Works well for fractional knapsack

Weaknesses:

  • Fails for 0-1 knapsack problems
  • Does not explore all possible options
  • Doesn't guarantee optimal solution

Dynamic Programming

Strengths:

  • Suits 0-1 knapsack nature of problem
  • Handles overlapping subproblems
  • Guarantees optimal solution

Weaknesses:

  • Higher space and time requirements
  • Requires careful memory management

Why We Chose Dynamic Programming

We select Dynamic Programming (DP) because our relief-packing problem is a classic 0-1 knapsack problem. In this scenario each item can either be taken or left behind (0-1 choice). The goal is to maximize the total value (urgency) of items loaded in a boat without exceeding its weight limit.

Knapsack Problem Analogy

  • Items: The relief supplies (each with a weight w_i and a value v_i)
  • Capacity: The boat's maximum weight W
  • Objective: Maximize Σv_i of selected items s.t. Σw_i ≤ W

Implementation

Problem Formulation

Formally, let there be n items. Each item i has weight w_i and value v_i. Boat capacity is W. We want to choose a subset S of items to maximize:

Σ v_i for i in S

subject to:

Σ w_i ≤ W for i in S

Each item is either taken (1) or not (0), giving it the 0-1 knapsack structure.

Correctness Proof

Problem Statement

The objective is to maximize the total value based on the urgency and the significance of the items to the rescue efforts in the context of limited boat's limited maximum carrying capacity.

Base Case

In our problem, we initialize the DP table with size (n+1) * (W+1) such that:

dp[0][w] = 0 for all w in 0 to W

This indicates if there are 0 items, the maximum value the boat can carry is 0. This is correct as no items will yield zero value.

Induction Hypothesis

We assume that for all items 1 to i-1 and all weight capacities 0 to w, the DP table dp[i-1][w] correctly represents the maximum total value of the items that can be packed into a boat of weight capacity w using only the first i-1 items.

Induction Step

For each item i with weight[i] and value[i], the algorithm considers two cases:

  1. The item is not included: dp[i][w] = dp[i - 1][w]
  2. The item is included: dp[i][w] = dp[i - 1][w - weight[i]] + value[i]

Assuming the induction hypothesis, both values are correctly computed.

Final State

After processing all items, dp[n][W] represents the maximum value attainable. The backtracking phase correctly reconstructs which items were included by checking where:

dp[i][w] != dp[i - 1][w]

Thus, the algorithm by induction is correct and ensures the optimal solution is selected.

Algorithm Analysis

Complexity Analysis

We analyze the time and space complexity of the algorithm in the worst, average, and best cases.

Time Complexity

Key Parameters:

  • n = number of items
  • W = total maximum capacity

The algorithm uses nested loops:

  • Outer loop runs n times
  • Inner loop runs W+1 times

Total operations: O(nW)

Best, average, and worst case: O(nW)

Space Complexity

We create a 2D array of size (n+1) × (W+1):

Space required: O(nW)

Can be optimized to O(W) using a rolling array approach

Efficiency Summary

For small to medium-sized problems, the 0-1 Knapsack method employing Dynamic Programming offers an optimal solution.

The O(nW) complexity makes it efficient for:

  • n ≤ 1000
  • W ≤ 100,000

For larger problems, approximations or optimizations may be needed.

Program Testing

Testing Methodology

We tested the program extensively to ensure correct behavior under various scenarios:

Unit Tests

Small, easily verifiable examples (like textbook knapsack problems).

Example: W=4, items (weight [4,5,1], value [1,2,3]) → optimal solution picks item with weight 1 and value 3.

Edge Cases

  • No items (n=0): Outputs no items selected, total value 0
  • Zero capacity (W=0): Chooses nothing, value 0
  • All items heavier than capacity: Outputs no items, value 0
  • Single item: Correctly includes if weight ≤ W

Typical Tests

Randomized tests with larger n and W to check performance.

Manually verified that no combination yields a higher value than the program's output.

Testing Summary

The algorithm passed all tests. No discrepancies were found, confirming both correctness and stability. Performance remained acceptable even for worst-case reasonably sized inputs.
